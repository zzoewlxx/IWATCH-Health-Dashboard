# IWATCH Health Dashboard

把 iPhone「健康」App 导出的数据，变成一个**本地离线看板**和一份**可以用 SQL 查询的数据库**。
放入导出文件、运行一条命令即可更新；数据全程不离开你的电脑。

*Turn an Apple Health export into a local, offline dashboard and a queryable SQLite database. One command to update; your data never leaves your machine.*

## 参考区间与证据

光有曲线看不出“这算好还是不好”。本项目把每个用来对照的区间都写进一份证据表 [pipeline/reference.json](pipeline/reference.json)，看板的「数据说明」页会原样列出：

- **怎么算**：窗口长度和界线都在这份文件里，计算代码直接读取，改了文件，结果就跟着变。
- **证据等级**：A 是指南、共识或大型荟萃分析；B 是队列研究或小样本试验，人群或测法和这里不完全相同；C 是经验做法或仍有争议，只作提醒。
- **出处**：每条都有文献或官方页面的链接，并标明核对到了哪一步（全文、摘要、官方页面，或只见过转述）。
- **没有采用的指标**也写明原因，比如全天 HRV 均值、睡眠效率、睡眠分期占比、单次血氧读数。

几条原则：

1. 个体差异大的指标（HRV、静息心率、呼吸频率、手腕温度）只和你自己的基线比；有公认指南的指标（睡眠时长、步数、运动量）才用人群标准。
2. 看一段时间的均值，不看单独一天。
3. 每个数值只用当天和之前的数据计算，所以过去某一周的结果不会因为后来的数据而改变。
4. 没有提示不等于没有问题，有提示也不等于有问题。这些内容帮你了解自己，不是诊断。

每次更新会逐日算出下面这些指标，写进 `health.db` 的 `analysis` 表：

| 类别 | 指标 |
|---|---|
| 恢复 | 夜间 HRV 近 7 晚均值和个人平稳带、静息心率近 7 天均值和个人基线、当晚有几项夜间体征明显偏离 |
| 睡眠 | 近 7 天平均时长和短睡晚数、近 14 天睡眠欠账、作息规律指数（SRI）、入睡时间和睡眠时长的波动 |
| 日常活动 | 近 7 天日均步数、锻炼分钟合计、力量训练天数 |
| 训练 | 每次训练的负荷（费力度 × 分钟）、近 7 天负荷与此前 4 周的比值、距离上次训练的天数 |

发现出处有误，或者有更好的证据，欢迎提 issue 或直接修改 `reference.json`。

### 耳机与听力

用耳机听歌、看视频时，iPhone 和 iPad 会把耳机里的音量写进健康 App（电话不计入）。「耳机」页是最早做成港片的一页（《重庆森林》的夜里）：霓虹红、钨丝灯黄、荧光青。开场是一格宽银幕画面，后面分成「时间、夜、声音、入睡之前」几幕，每一幕配一句按你自己的数字写的旁白，最后是演职员表。顶部可以切换看全部耳机或其中一副（“胶卷”），时间范围（全部 / 一年 / 90 天 / 30 天 / 7 天）和日期直接在页面里改，日历、时钟、星期和音量卡片都可以点。它把这些记录整理成：

- **收听时长**：每天听了多久、一周里哪几天听得多、一天中的什么时候在听。两条记录重叠的部分只算一次。
- **音量和声音剂量**：平均音量按收听时长做能量平均（一小时 70 分贝加一小时 60 分贝，平均约 67 分贝，而不是 65）。声音剂量按 WHO 与国际电信联盟的安全收听标准计算：80 分贝听 40 小时为每周的 100%，音量每高 3 分贝，能听的时间减半。Apple 的耳机音量提醒用的是同一条线。周报只在 7 天剂量达到 100% 时提一句。
- **耳机**：每一副耳机听了多久、平均多大声、第一次和最近一次用的日期。型号来自记录里的设备信息，蓝牙地址不会保存。AirPods 和 Beats 的音量是按型号测的，最准；其他耳机是按音量估算的。
- **每一次收听**：中间停顿不超过 5 分钟、用同一副耳机的记录算作一次；可以看每次听多久、最长的一次和全部明细。
- **收听性格**：按“出勤率、每次听多久、夜里听的比例”给一个好玩的称呼，只是描述，不是评价。
- **入睡前后**：入睡前一小时和入睡后一小时有没有在听，收听结束到入睡通常隔多久。
- **听力测试**：AirPods Pro 听力测试（或其他 App 写进健康 App 的听力图）。每只耳朵取 500、1000、2000、4000 Hz 的平均听阈，按 Apple 结果页用的分级显示；有多次测试时列出每次的变化。这是自测，不是诊断。

### 周报

看板打开后默认是「周报」。每个周日出一期，另外总有一期覆盖最新的 7 天。每一期包括：

- **一句话结论和最多三条建议**。每条建议用一句股市梗当标题，比如“三倍做多力量训练”“重点关注睡眠 ETF”“被沙发套牢 12 天，择机复牌”：绕个弯说，更容易记住。旁边紧跟着一句大白话的意思。每条建议都能展开，看到触发它的具体数字、对应的参考区间和证据等级，并可以跳到出处。
- **两个分数**：睡眠（时长 60 分 + 规律 40 分）和日常活动（步数 40 分 + 运动分钟 40 分 + 力量训练 20 分），表示这 7 天对照指南完成了多少。
- **两个状态**：恢复和训练负荷只能和你自己的过去比，谈不上完成度，所以不打分。

这份周报想帮你了解自己，而不是让你焦虑，所以有几条约定：

- 只说记录到了什么（“手表记录到平均每晚睡 6 小时 12 分”），不替你下结论；给一个可以试试的小动作，不下命令；不用吓人的词。股市梗只用在建议上，风险也只用“股灾”“套牢”“爆仓”这样的玩笑话点到为止；和身体信号有关的几条（夜间体征、HRV、静息心率）只说“先别加仓”“减仓观望”这类轻话，不拿身体开玩笑。
- 夜间 HRV 要连续 3 天低于你的平稳带才提示。只看某一天的话，偶尔低于平稳带很常见，多数没有意义。
- 睡眠欠账只作背景信息。只有 7 天平均不到 6.5 小时，或者有 3 晚不足 6 小时，才建议补觉。
- 手表多半被摘下的夜晚和白天不参与判断：睡眠记录结束后一小时内没有任何心率读数、而且明显短于平时的夜晚，多半是半夜摘了表或没电，不计入睡眠时长（醒来就摘表充电、睡眠时长正常的照常计算）；全天有心率读数的时段不到 40% 的日子，不把“0 分钟锻炼”当真。

分数里各部分的权重是本项目自己定的，没有文献依据，同样写在 `reference.json` 里。它们适合拿来和自己的往期比，不适合和别人比。

### 长期变化和给医生的小结

周报里还有一栏「长期变化」，看的是近 1 到 6 个月。一共 7 项：静息心率的长期变化、睡眠血氧、睡眠呼吸紊乱、长期睡眠偏少、体重变化、夜间体征反复偏离、心电图记录。只有持续了一段时间的变化才会列为“值得留意”，单独一晚或一周不会。

被列出来时，它只说三件事：记录里什么变了，这种变化常见的原因有哪些，以及如果一直这样又想不到原因，可以带着记录去哪类门诊问问。它不会说你得了什么，也不能判断原因。

「小结」页把近三个月的主要指标、睡眠与活动、长期变化检查、被标出的夜晚、心电图记录和你的标注整理成一页，点“打印 / 存为 PDF”就能带去看医生。

### 回测

「回测」页回头看整段记录，帮你判断这些界线对你合不合适：

- 每条建议在历史上出现过多少期、分别在什么时候。
- 换一个界线会怎样。比如“日均步数低于多少提示多走”，页面会列出 4,000、5,000、6,000、7,000 步各会触发多少期。想改就改 `reference.json`，重新运行更新即可。
- 被标出的夜晚和你的标注对照：标了“生病”“饮酒”的日子，当晚或次晚有没有被标出，各项体征平均偏离多少。这需要你先在 `标注.csv` 里记下一些日子。

## 它解决的两个准确性问题

直接把导出文件里的数字加起来，结果通常是错的：

1. **多设备重复计数**。手机和手表（或手环）会同时记录步数、能量、距离。本项目按时间段和来源优先级去重：同一时刻取优先级最高的设备，低优先级记录中重叠的那部分时间按比例扣除。
2. **时区**。导出文件把所有时间统一写成导出时手机所在的时区。出过国、换过时区的日子，按天统计和作息时间都会错位。本项目根据睡眠和训练记录里的时区信息还原当时所在地；没有时区信息的时段，用 Apple 自己保存的每日汇总反推。

每次更新都会把去重后的活动能量与 Apple 的每日汇总逐日对账，并把偏差打印出来，结果也显示在看板的「数据说明」页。

## 快速开始

> 第一次用、不太熟悉电脑操作，或者想发给朋友用：看图文版的 [使用指南.html](使用指南.html)（下载后用浏览器打开）。

**需要**：Python 3.9 或更高版本。不依赖第三方库（Windows 需要 `tzdata` 时区数据包，一键脚本会自动安装）。

1. **导出**：iPhone 健康 App → 右上角头像 → 最下方「导出所有健康数据」，得到一个 zip。
2. **放入 `数据集/` 文件夹**：zip 直接放进去即可，不用解压（解压后的文件夹也认，子文件夹随意）。
3. **运行**：
   - Windows：双击 `更新数据.bat`
   - macOS / Linux：`python3 pipeline/update.py`

约十几秒后看板自动在浏览器打开。以后每次导出，重复第 2、3 步即可；脚本会自动选用**导出时间最新**的那一份。

只想看看板、不更新数据：直接打开 `dashboard/index.html`。

可选参数：

```
python pipeline/update.py --export <某个导出文件夹或zip>   # 指定用哪一份
python pipeline/update.py --data <目录>                    # 换一个存放导出的目录
python pipeline/update.py --no-open                        # 完成后不打开浏览器
python pipeline/update.py --no-db                          # 不生成 health.db
```

## 看板用法

- 「周报」里用“上一期 / 下一期”翻看，或者在最下面的「往期」表里点某一行；点「逐日记录」里的一行会跳到那一天。
- 指标卡上的 ▲▼ 是和**前一个等长时间段**比（选 90 天，就是和再往前的 90 天比）。
- 鼠标悬停看具体数值；每张图右上角的「表格」可展开底层数字；点图例可隐藏 / 显示某条线。
- **日视图下点击图上任意一天**（或日历里的一格）会跳到「单日」页。
- 静息心率、HRV 等图上的浅色带是**个人基线范围**（此前 28 天的均值 ± 1 个标准差）。数值跑出色带，才是相对你自己平时的真实变化。
- 图上的竖线标出某项指标的主要数据来源发生变化（比如换了设备）的日期，两侧数值不宜直接比较。

## 用 SQL 查询：`health.db`

每次更新会同时生成一个 SQLite 数据库，用 `sqlite3`、[DB Browser for SQLite](https://sqlitebrowser.org/) 或任何支持 SQLite 的工具都能打开。

| 表 / 视图 | 内容 |
|---|---|
| `daily` | 每天一行，看板上的所有指标各占一列 |
| `analysis` | 每天一行，个人基线、作息规律、训练负荷等分析指标 |
| `reports` | 每期周报一行：两个分数、两个状态、一句话结论、建议、值得留意的长期变化 |
| `metrics` | `daily` 和 `analysis` 各列的中文名和单位（数据字典） |
| `monthly`、`weekly` | `daily` 各列的月均、周均（视图） |
| `records` | 每一条原始采样，带类型、来源、当地时间（视图） |
| `sleep_segments` | 每晚的睡眠分期片段 |
| `workouts` | 每次训练一行，含心率区间用时和训练负荷 |
| `annotations` | 你自己对某些日子的标注，每个标签一行 |
| `activity_summary` | Apple 自己保存的每日圆环汇总 |
| `timezones` | 每个时间段所在的时区及判断依据 |
| `ecg` | 心电图记录（不含波形） |
| `headphone_devices` | 每一副耳机：收听时长、平均音量、用过的天数、播放设备 |
| `headphone_sessions` | 每一次收听：开始和结束时间、时长、平均音量、耳机 |
| `hearing_tests`、`hearing_test_points` | 听力测试：每只耳朵的四频平均和分级，以及每个频率的听阈 |
| `audio_events` | 耳机音量提醒和环境噪音提醒 |

两点注意：

- 对步数、能量、距离这类**累计型**指标求和时用 `counted` 列（去重后计入的量），不要用 `value`，否则会重复计数。
- 按天的数字以 `daily` 表为准：它会把跨午夜的采样按时长拆到两天，而 `records` 按采样的开始时间归日。

示例：

```sql
-- 每月平均
SELECT month, steps, sleep_total, rhr, hrv, weight FROM monthly;

-- 每天步数（已去重）
SELECT local_date, ROUND(SUM(counted)) AS steps
FROM records WHERE type = 'StepCount' GROUP BY local_date;

-- 工作日和周末的睡眠时长
SELECT CASE WHEN weekday >= 6 THEN '周末' ELSE '工作日' END AS kind,
       ROUND(AVG(sleep_total), 2) AS hours, COUNT(sleep_total) AS nights
FROM daily GROUP BY kind;

-- 最近 30 天，一天中各小时的平均心率
SELECT substr(local_time, 1, 2) AS hour, ROUND(AVG(value)) AS bpm
FROM records
WHERE type = 'HeartRate'
  AND local_date >= date((SELECT MAX(date) FROM daily), '-30 days')
GROUP BY hour;

-- 有训练的日子，第二天的 HRV 和没训练的日子相比
SELECT CASE WHEN w.date IS NULL THEN '前一天没训练' ELSE '前一天有训练' END AS kind,
       ROUND(AVG(d.hrv), 1) AS hrv, COUNT(d.hrv) AS days
FROM daily d
LEFT JOIN (SELECT DISTINCT date FROM workouts) w ON w.date = date(d.date, '-1 day')
GROUP BY kind;

-- 每周日的快照：夜间 HRV 是否在自己的平稳带内、作息规律指数、训练负荷比
SELECT a.date, hrv7, hrv_lo, hrv_hi, sri28, sleep_debt14, load_ratio, steps7
FROM analysis a JOIN daily d ON d.date = a.date
WHERE d.weekday = 7 ORDER BY a.date DESC LIMIT 12;

-- 最近 12 期周报
SELECT end_date, sleep_score, activity_score, recovery, training_load, suggestions
FROM reports ORDER BY end_date DESC LIMIT 12;

-- 每月的耳机收听：有收听的日子里平均每天几分钟、平均音量、7 天声音剂量的最高值
SELECT substr(date, 1, 7) AS month, ROUND(AVG(listen_min)) AS minutes_per_day,
       ROUND(10 * log10(SUM(listen_min * power(10, headphone / 10)) / SUM(listen_min)), 1) AS avg_db,
       MAX(hp_dose7) AS max_weekly_dose_pct
FROM daily WHERE listen_min > 0 GROUP BY month;

-- 每副耳机用了多少小时
SELECT device, ROUND(minutes / 60.0, 1) AS hours, avg_db, first_date, last_date FROM headphone_devices;

-- 同一晚有两项以上夜间体征明显偏离个人基线的日子，以及当天的标注
SELECT a.date, vitals_out, z_sleep_hr, z_sleep_hrv, z_resp, z_wrist_temp, z_sleep_spo2, n.tag
FROM analysis a LEFT JOIN annotations n ON n.date = a.date
WHERE vitals_out >= 2;
```

## 设置

把 `config.example.json` 复制为 `config.json` 再修改（`config.json` 不会被 git 跟踪）：

```json
{
  "data_dir": "数据集",
  "source_priority": [],
  "timezone_overrides": [],
  "sleep_need_hours": 8
}
```

- `source_priority`：多设备同时记录时谁优先。默认 Apple Watch → iPhone → 其他 App。想让某个来源排最前，写它名字里的关键字，例如 `["手环", "Watch"]`。
- `timezone_overrides`：自动还原的时区不对时手动指定，例如
  `[{"from": "2024-05-01", "to": "2024-05-07", "tz": "Europe/Paris"}]`。
- `sleep_need_hours`：你每晚需要睡多久，用来计算睡眠欠账，默认 8。建议按自己不设闹钟时自然能睡多久来填。

## 标注关键日子

生病、饮酒、熬夜、出差，这些日子的数据往往和平时不一样。记下来，以后看数据时就知道原因。

把 `标注.example.csv` 复制为 `标注.csv`，按“日期, 标签, 备注”填写：

```
日期,标签,备注
2025-03-08,生病,感冒发烧
2025-03-21,饮酒、熬夜,朋友聚餐
```

下次更新时会读进来：在「单日」页显示，并写入 `health.db` 的 `annotations` 表。用 Excel 或记事本编辑都可以，UTF-8 和 Excel 在中文系统上默认保存的编码都能识别；一格里写多个标签时用顿号或逗号隔开。`标注.csv` 不会被 git 跟踪。

## 计算口径（简版）

- **睡眠**：一个「睡眠日」是当地时间前一天 18:00 到当天 18:00，记在醒来那天，包含小睡。同一晚有多个来源时优先采用带分期的来源；只有「卧床」记录的夜晚单独标灰，不计入睡眠时长。
- **心率**：全天平均按 5 分钟分箱后再平均，避免训练时的密集采样把均值拉高。
- **圆环**：活动能量、锻炼分钟、站立小时优先采用 Apple 的每日汇总；没有汇总的日子用去重后的记录求和。
- **趋势线**：日视图的粗线是 7 日滑动平均；周 / 月视图取该周 / 月内有数据日子的平均值，周从周一开始。
- **导出当天**：全天累计类指标不完整，会从该日剔除。

完整说明在看板的「数据说明」页。

## 隐私

- 所有处理都在本机完成：脚本只读本地文件，看板是纯本地网页，不联网、不上传。
- `.gitignore` 已经排除了 `数据集/`、`dashboard/data.js`、`dashboard/intraday.js`、`health.db`、`config.json` 和 `标注.csv`。如果你 fork 了这个项目，**不要把这些文件提交上去**，它们包含你的全部健康记录。

## 局限

- 只做数据整理、展示和与参考区间的对照，**不构成医疗诊断或建议**。「长期变化」没有列出任何一项，也不代表没有问题；身体不舒服时请直接就医，不要等数据。
- 个人基线需要先积累数据：夜间 HRV 和静息心率的基线要求此前 60 天里至少有 20 天的数据，作息规律指数要求最近 28 对相邻日里至少 14 对有睡眠记录。刚开始戴表的头两个月，这些指标会是空的。
- 不同设备的算法不同（尤其是静息心率和睡眠分期），换设备前后的数值不宜直接比较。
- 心电图的「估算心率」由本项目根据 R 波间距计算，不是 Apple 给出的数值。
- 运动轨迹（GPX）目前没有可视化。
- 目前只在中文系统的导出（`导出.xml`）上实际验证过。英文系统的 `export.xml` 同样会被识别，但没有充分测试。

## 项目结构

| 路径 | 作用 |
|---|---|
| `数据集/` | 放 iPhone 导出的 zip 或解压后的文件夹 |
| `更新数据.bat` | Windows 一键更新 |
| `pipeline/update.py` | 入口：解析 → 去重 → 时区 → 汇总 → 分析 → 输出 |
| `pipeline/hk/` | 各步骤的实现（解析、时区、去重与按天汇总、睡眠、训练与心电、耳机与听力、分析、周报、长期筛查、回测、标注、SQLite） |
| `pipeline/reference.json` | 证据表：参考区间、计算参数和出处 |
| `dashboard/` | 看板页面（原生 JS + ECharts，无需构建） |
| `标注.example.csv` | 标注文件的模板 |
| `使用指南.html`、`docs/guide/` | 图文版使用指南和其中的截图（截图用的是虚构的演示数据） |
| `tests/` | 单元测试，只使用合成数据 |
| `health.db` | 生成的 SQLite 数据库（不入库） |

运行测试（同样不需要第三方库）：

```
python -m unittest discover -s tests
```
